# AdaptFit MVP — Implementation plan

Status: **all stories AF-01 … AF-09 implemented** (40 / 40 points). This document is the living plan used during the build; the "Status" column reflects the final state.

## 1. Scope

Local-first, mobile-first fitness PWA. Core loop: **check in → recommendation → active session → history**, plus pixel-character progression, offline install/use, and data ownership (export / restore / reset).

Out of scope (per brief): accounts, cloud sync, external AI, telemetry, ads, payments, wearables, remote assets, medical/injury programming, calorie prescriptions, automatic load increases.

## 2. Architecture decisions

| Decision | Choice | Why |
|---|---|---|
| Stack | React 19, TypeScript 6.0 (strict), Vite 8, npm | Brief. TS pinned to 6.0.x because `typescript-eslint` 8.72 supports `<6.1`. |
| Storage | IndexedDB via Dexie 4 (`liveQuery`) | Transactions, versioned schema, cross-tab change propagation. |
| Validation | Zod 4 (backup import only, lazy-loaded) | Keeps the main bundle at ~413 kB; backup chunk loads on demand. |
| PWA | `vite-plugin-pwa` 2 (Workbox `generateSW`, `registerType: 'prompt'`) | Precaches the shell; updates wait for the user's **Refresh** tap and the banner is hidden during an active workout. |
| Routing | Hash routes (`#/today`, `#/history`, `#/character`, `#/settings`, `#/workout`, `#/done/:id`) | Zero dependency; works trivially offline with the navigation fallback. |
| Styling | Plain CSS + design tokens (`src/ui/tokens.css`) | No CSS framework; pixel art only in the character, badges, and celebration. |
| Time | `src/ui/clock.ts` is the app's only "now"; domain functions take `now` (and optional `timeZone`) as arguments | Deterministic tests; Playwright controls time via `page.clock`. |
| Progress | Derived from completed sessions on every read | No separate XP balance that can drift. Duplicate records count once. |
| One active workout | Check-and-insert inside one `rw` IndexedDB transaction | IndexedDB serialises overlapping `rw` transactions, so double taps and two tabs cannot create two active sessions. Completion is idempotent the same way. |
| Security | Production-only CSP meta (`script-src 'self'`, `connect-src 'self'`); imported text rendered as React text | No external scripts, fonts, or connections. Dev keeps Vite's inline preamble working. |

### Recommendation engine (deterministic)

1. **Safety** — pain / illness / unsafe → rest, no plan object at all.
2. **Time** — `<5` min → rest ("check in later"). Bands 5–14, 15–29, 30–60. Estimates = warm-up + Σ(sets × work + (sets−1) × rest) + 20 s transitions, rounded up. Plans must fit; prefer the user's band, fall back to shorter bands.
3. **Energy / soreness** — low energy or high soreness → `gentle` templates (fewer sets) only, else rest. `hard` only with high energy and intermediate+ experience. Missed days never raise intensity (history only feeds rule 5).
4. **Equipment / experience** — each block resolves to its exercise or the first safe substitution the user can do; otherwise the template is excluded. Within the chosen band: own-equipment templates → other owned equipment → substituted → bodyweight fallback.
5. **Recent training** — if a candidate with a different emphasis exists, drop emphases completed in the last 24 h; if none, a gentle full-body option, else rest.
6. **Rank** — goal fit ↓, estimate ↓, template ID ↑.

Every result carries `inputs`, reason codes, and a display sentence (e.g. "You have 20 minutes and low energy today, so this plan uses fewer sets and a gentler pace.").

## 3. Storyboard → implementation

| Frame | Screen / component |
|---|---|

| 8. Settings | `features/settings/SettingsScreen.tsx`, `RestoreBackup.tsx` (export, validate-then-confirm restore, confirm reset). |
