# AdaptFit V0.4 — Installing the app, and future native packaging

## What V0.4 ships

- Installable Progressive Web App: `manifest.webmanifest` (name, `standalone`
  display, portrait, theme `#101418`, 192/512/maskable icons), service worker
  (Workbox, precaches the whole app shell — about 1 MB — including lazy screens).
- iOS: `apple-touch-icon`, `apple-mobile-web-app-capable`, black-translucent
  status bar, 8 launch (splash) images for current iPhone sizes, `viewport-fit=cover`
  with `env(safe-area-inset-*)` padding.
- Android: icon and splash generated by Chrome from the manifest.
- Keyboard: `interactive-widget=resizes-content`; the bottom navigation hides
  while a text field is focused; the focused field is scrolled into view.
- Offline: every screen works without a connection after the first visit to the
  installed version. Data is in IndexedDB on the device.
- No App Store / Google Play account is needed.

Icons and splash screens are original artwork generated by
`node scripts/generate-icons.mjs`.

## Important: installing needs HTTPS

Phones only allow installing and offline mode (service workers) on a secure
origin: `https://…` or `localhost` on the same device. Opening
`http://192.168.x.x:4173` from a phone works for trying the app, but it will
**not** install properly or work offline. Options:

1. **Static HTTPS hosting** (recommended for daily use): upload `dist/` to any
   static host with HTTPS (e.g. GitHub Pages, Netlify, Cloudflare Pages). The app
   is static files only; your data stays on each phone.
2. **Private local certificate** (mkcert): serve `dist/` over HTTPS on your home
   network and install mkcert's root certificate on the phone (iPhone: install the
   profile, then Settings → General → About → Certificate Trust Settings).

Data is stored per device and per web address. Moving to a new address starts
empty: use **Settings → Data & backups → Export** on the old one and **Restore**
on the new one.

## Install on iPhone (Safari)

1. Open the HTTPS address in **Safari** (other iOS browsers can't install web apps on older iOS versions).
2. Tap **Share** (square with arrow) → **Add to Home Screen** → **Add**.
3. Open AdaptFit from the new icon. It runs full screen, without Safari's bars.
4. Open it once while online so the offline copy is stored (Settings → Install the app shows "Offline: ready").
5. Updates: when a new version is available the app shows "A new version is ready" → **Refresh**. Nothing updates mid-edit.

iOS may clear website data for apps that aren't used for several weeks if the
device is low on storage. Export a backup regularly.

## Install on Android (Chrome)

1. Open the HTTPS address in **Chrome**.
2. Tap **⋮** → **Install app** (or **Add to Home screen**), or accept the install banner.
3. Open from the launcher; it runs in its own window and works offline.

## Future native packaging (recommendation)

Use **Capacitor** to wrap the existing build when App Store / Play distribution
is wanted:

- `npm i @capacitor/core @capacitor/cli @capacitor/ios @capacitor/android`,
  `npx cap init AdaptFit com.example.adaptfit --web-dir dist`, `npx cap add ios`,
  `npx cap add android`, then `npm run build && npx cap sync` on every release.
- **No business logic is duplicated:** `src/domain` (parser, weekly records,
  analysis, coaching) and `src/data` (Dexie/IndexedDB) run unchanged inside the
  native WebView. Hash routing already works under `capacitor://` / `file://`.
- Keep the service worker for the web build only (Capacitor serves files
  locally; disable SW registration when `Capacitor.isNativePlatform()`).
- Optional native extras later, each behind a small adapter in `src/platform/`:
  `@capacitor/preferences` or SQLite for storage durability, local
  notifications for the weekly reminder, Share sheet for backups, Haptics.
- Requirements at that point: Apple Developer Program and Google Play Console
  accounts, privacy labels (no data collected), and app review assets
  (`docs/screenshots/v0.4` can seed them).

Rewriting in Swift, Kotlin or React Native is not recommended: it would
duplicate the domain logic and its tests for no user-visible gain.
